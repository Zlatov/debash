# debash

> Минималистичный AI-помощник для терминала.

---

# Философия проекта

## Зачем существует debash

Современные AI-инструменты отлично помогают писать код, но практически не помогают выполнять ежедневные рутинные действия разработчика.

Каждый день приходится выполнять десятки похожих операций:

* очистить кэш;
* перезапустить Docker-контейнер/-ы;
* скачать тестовую базу;
* восстановить локальную БД;
* почистить логи;
* проверить состояние контейнеров;
* выполнить миграции.

Все эти задачи требуют множества консольных команд, знания структуры проекта и понимания текущего состояния системы.

Обычные shell-скрипты плохо подходят для подобных задач, потому что они не умеют принимать решения.

Большие AI-помощники (Claude Code, Gemini CLI и т.п.) умеют значительно больше, чем требуется, имеют сложный интерфейс и ориентированы прежде всего на написание кода. Небольшие задачи в таких помошниках засоряют историю бесполезными сессиями. Промт помошников уже занят описанием под разработку, а не под консольные команды.

**debash создаётся для другой цели.**

Это не IDE.

Это не Copilot.

Это не редактор кода.

Это не универсальный AI-агент.

Это умный терминальный помощник, который умеет понимать естественный язык и выполнять необходимые bash-команды внутри текущего проекта.

---

# Главная идея

debash настраивается под рутинную работу с разрабатываемым приложением.

Debash изучает его так же, как это сделал бы живой разработчик.

При необходимости он самостоятельно:

* читает README;
* читает CLAUDE.md;
* читает AGENTS.md;
* изучает Makefile;
* изучает docker-compose.yml;
* просматривает scripts/;
* анализирует структуру проекта.


После этого принимает решение, какие команды необходимо выполнить. Удачные варианты команд сохраняет в ограниченный список, что бы далее легче понимать пользовательские требования «Подними/перезапусти». Можно заранее подготовить DEBASH.md для списка рутинных задач или базовых команд которыми debash может воспользоваться.

---

# Основной принцип

Вместо десятков специализированных инструментов существует один основной инструмент:

> Выполнить bash-команду.

LLM сама решает:

* какие команды выполнять;
* в каком порядке;
* какие результаты анализировать;
* когда задача считается выполненной.

---

# Что НЕ является целью проекта

debash не должен превращаться в аналог Claude Code.

Он не должен:

* редактировать код;
* становиться IDE;
* заниматься автодополнением;
* содержать десятки встроенных инструментов;
* иметь систему проектов, Workspace и сложную конфигурацию.

Чем проще — тем лучше.

---

# Каким должен быть интерфейс

Единственный интерфейс — терминальный чат.

Пример:

```
$ debash

────────────────────────────────────────

Debash

────────────────────────────────────────

> обнови локальную базу

✔ Docker работает

✔ скачиваю dump

✔ восстанавливаю БД

✔ очищаю кэш

✔ произвожу миграции

✔ готово

>
```

Никакого браузера.

Никаких вкладок.

Никаких облачных рабочих пространств.

Только терминал.

# Принципы поведения

## Минимум магии

Пользователь всегда понимает, что сейчас происходит.

debash показывает:

* какую команду собирается выполнить;
* зачем она нужна;
* результат выполнения.

---

## Думает, потом действует

Перед выполнением команд debash сначала пытается понять текущее состояние проекта.

Например:

* работают ли контейнеры;
* существует ли нужная база данных;
* доступны ли необходимые сервисы.

Только после этого принимает решение.

---

## Использует знания проекта

Если в проекте уже существуют:

* Makefile;
* shell-скрипты;
* rake-задачи;
* bin-команды;

следует использовать именно их, а не изобретать новые последовательности команд.

---

## Изучает проект самостоятельно

Если необходимая информация отсутствует в контексте, debash сначала исследует проект.

Например:

```
ls

find

cat README.md

cat Makefile

cat docker-compose.yml
```

После чего принимает решение.

---

## Не делает опасных действий молча

Перед потенциально опасными операциями требуется подтверждение пользователя.

Например:

* rm
* git reset
* docker compose down -v
* drop database
* force push

---

## Работает относительно текущей директории

Если пользователь запустил

```
cd my_project
debash
```

то все команды автоматически выполняются внутри этой директории.

---

# Предпочтительный сценарий использования

Вместо:

```
docker compose ps

docker compose restart

docker compose exec web rails tmp:clear

docker compose exec web bundle exec rake ...

...
```

Пользователь пишет:

```
перезапусти проект
```

или

```
обнови локальную базу
```

или

```
почему не запускается Sidekiq?
```

А debash самостоятельно определяет последовательность необходимых действий.

# Стек технологий (MVP)

Язык:

* Node.js

Интерфейс:

* терминальный чат (TUI)

LLM:

* DeepSeek API

Конфигурация:

* YAML или TOML

Контекст проекта:

* README.md
* CLAUDE.md
* AGENTS.md
* DEBASH.md (если существует)
* .debash/cache (ограниченный стек удачных команд)

Основной инструмент:

* выполнение bash-команд через безопасную обёртку над subprocess.

# Главная мысль проекта

debash не должен быть самым умным AI.

Он должен быть самым удобным способом сказать компьютеру человеческим языком:

> «Разберись с этим проектом и определи в каком он состоянии, что бы выполнить с ним те операции которые мне нужны, показывая что происходит».
