# Этапы разработки debash

Каждый этап — маленький и самостоятельно тестируемый. Проверка всегда
проходит в роли конечного пользователя: человека, который ничего не знает
о внутренностях, просто ставит пакет и пробует им пользоваться.

Начиная с этапа 1 (инфраструктура публикации) каждый следующий этап
заканчивается публикацией новой версии в npm — тестируем не локальный
`node index.js`, а именно `debash`, поставленный через
`npm install -g debash`.

---

## Открытые решения (зафиксировать перед стартом)

* **Имя пакета:** `debash` — свободно на npm (проверено 2026-07-30), скоуп
  не нужен.
* **Репозиторий:** публичный (open source).
* **Лицензия:** MIT (стандарт для такого рода CLI-утилит, если не нужно
  иное — подтвердить).
* **npm-аккаунт:** нужен `npm login` (интерактивно, вручную пользователем)
  перед первой публикацией.
* **GitHub-репозиторий:** создать вручную либо через `gh repo create`,
  если `gh` будет установлен и авторизован.

---

## Этап 0 — Скелет CLI

Node.js проект, `package.json`, точка входа `bin/debash`, при запуске
печатает заголовок/пустой промпт из манифеста и ничего не падает.

**Тест:** `node bin/debash.js` → видно шапку, процесс не падает,
`Ctrl+C` выходит.

---

## Этап 1 — Публикация: git + npm

* `git init`, публичный репозиторий на GitHub.
* `package.json`: `name: debash`, `bin`, `license: MIT`, `files`,
  минимальный README для npm-страницы.
* `npm login` (вручную) → `npm publish` версии `0.1.0`.

**Тест:** на чистом окружении `npm install -g debash`, затем просто
`debash` в любой директории — видно тот же заголовок, что и на этапе 0,
но теперь это уже реальный глобальный пакет, а не локальный скрипт.

---

## Этап 2 — REPL-цикл без LLM

Терминальный чат: читает ввод, эхо-ответ, `exit`/`Ctrl+C` для выхода.
История в рамках сессии.

**Тест:** `npm update -g debash` → пишешь что-то в промпт, видно, что
ввод принимается и цикл живой.

---

## Этап 3 — Подключение LLM (DeepSeek)

Системный промпт, отправка сообщения → вывод ответа. Ключ API через
`.env`/конфиг в домашней директории пользователя.

**Тест:** обычный вопрос ("привет, кто ты?") → осмысленный ответ модели.

---

## Этап 4 — Один инструмент: выполнение bash

LLM запрашивает выполнение команды (tool use), процесс выполняется,
stdout/stderr показываются в терминале и возвращаются модели.

**Тест:** "покажи файлы в этой папке" → реально выполняется `ls`,
результат виден.

---

## Этап 5 — Подтверждение опасных операций

Эвристика/список опасных команд (`rm`, `git reset`, `docker ... down -v`,
`drop database`, force push) → запрос `y/n` перед выполнением.

**Тест:** просьба сделать что-то деструктивное → предупреждение и явное
подтверждение, без него ничего не выполняется.

---

## Этап 6 — Изучение проекта (контекст)

Автозагрузка README.md, CLAUDE.md, AGENTS.md, DEBASH.md, если есть;
иначе самостоятельное исследование (`ls`, `find`, `cat Makefile` и т.п.)
перед принятием решения.

**Тест:** тестовый проект с Makefile/README, просьба "перезапусти
проект" → видно, что debash сначала читает файлы, потом использует
`make restart`, а не придумывает свою последовательность.

---

## Этап 7 — Кэш удачных команд (`.debash/cache`)

Сохранение успешных последовательностей команд под "намерение",
повторное использование при похожих запросах.

**Тест:** одна и та же просьба дважды → во второй раз видно, что debash
не переисследует проект заново.

---

## Этап 8 — Полировка UI

Рамки, ✔/✖-иконки, спиннер во время выполнения — как в примере из
манифеста.

**Тест:** визуальное сравнение вывода с примером в манифесте.

---

## Позже (за пределами MVP)

* несколько LLM (OpenAI, Anthropic, локальные модели);
* пользовательские команды, плагины;
* сохранение истории между сессиями;
* режим "только анализ" без выполнения команд;
* потоковое отображение вывода команд;
* MCP-подобные дополнительные инструменты.
